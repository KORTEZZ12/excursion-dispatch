# Процессы

Файлы `.bpmn` открываются в [Camunda Modeler](https://camunda.com/download/modeler/). SVG рядом с исходниками экспортированы из Модлера.

| Файл | Что показывает |
|---|---|
| `as-is-dispatch.bpmn` | Как группа доходит до гида сейчас. Три участника, всё общение между ними — сообщения. Аннотации отмечают боли П1–П4 и Н1 из [AS-IS](../research/as-is.md) |
| `to-be-guide-search.bpmn` | Поиск гида для одной группы: рассылка свободным гидам с учётом тихих часов, окно откликов и честный выбор (D-11), первое нажатие после пустого окна, эскалация по сроку, отмена в любой момент |
| `to-be-preparation.bpmn` | Подготовка назначенной группы: запрос подтверждения выхода, просьба о замене, эскалация, если гид молчит |
| `to-be-client-notice.bpmn` | Отписка клиенту: ждём назначения гидов, готовим текст, администратор отправляет в мессенджер клиента; до начала экскурсии сообщаем клиенту о смене гида |
| `to-be-daily-digest.bpmn` | Сводка на завтра каждый вечер всем гидам с группами |

## Исполнимость

В MVP схемы исполняет не Camunda, а планировщик в базе: каждому таймеру и типу задачи соответствует задание с тем же именем ([ADR-003](../decisions/adr/ADR-003-scheduler-not-camunda.md)). Схемы при этом остаются готовыми к развёртыванию в Camunda 8.


TO-BE подготовлены под Camunda 8.8 и проходят линтер Модлера без замечаний: у сервисных задач есть типы для воркеров, у сообщений — ключи корреляции, таймеры заданы через FEEL. AS-IS — описательная модель, процессы в ней не исполняемые.

Каждый процесс живёт в своём файле: у поиска гида, подготовки, отписки и сводки разный жизненный цикл и разный ключ экземпляра.

Таймеры с датой в прошлом срабатывают сразу. Поэтому группа, назначенная позже чем за 2 часа до начала, получает запрос подтверждения немедленно, без отдельной ветки.

## Договорённости для воркеров

- Если гид откликнулся из «Свободных групп» до рассылки, его отклик учитывается в окне вместе с остальными.
- Если администратор назначил гида вручную, пока окно открыто, `select-guide` ничего не выбирает и возвращает `assigned = true`: группа уже назначена.
- Пока открыта задача «Найти и назначить гида», назначение из бота или панели закрывает её автоматически (BR-26). Без открытой задачи назначение публикует сообщение `guide-assigned`.
- Таймер «Нет реакции дежурного» срабатывает через P-16 после создания задачи. Воркер `notify-all-admins` оповещает всех, только если задачу ещё никто не взял.
- Сообщение `all-guides-assigned` публикуется с TTL: если последнего гида назначили между проверкой и началом ожидания, процесс его не пропустит.
- Сообщение `guide-changed` публикуется, только если отписка по заявке уже отправлена. До отправки текст и так берёт актуального гида.
- При переносе времени текущий экземпляр `group-preparation` останавливается сообщением `assignment-ended`. Новый запускается, когда гид подтвердит новое время (BR-21).
- Таймер «Нет реакции дежурного» (P-16, BR-25) стоит на задачах администратора в поиске гида и подготовке группы. В отписке срок другой — крайний срок отправки P-11 (BR-16).
- Время сводки P-06 задано в таймере процесса `daily-digest` и меняется переразвёртыванием ([NFR-14](../requirements/nfr.md)).
