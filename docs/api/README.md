# Соглашения API

Версия 0.4. Контракт — [`openapi.yaml`](openapi.yaml): панель администратора и входящие вебхуки. Гиды работают через Telegram-бота, своего API у них нет. Документация в браузере: [kortezz12.github.io/excursion-dispatch/api](https://kortezz12.github.io/excursion-dispatch/api/).

## Проверка

```bash
npx @redocly/cli@1 lint openapi.yaml          # без ошибок и предупреждений, это же делает CI
npx @redocly/cli@1 build-docs openapi.yaml -o index.html
npx @stoplight/prism-cli mock openapi.yaml    # mock по примерам
```

## Правила

- **Повторы.** Все изменяющие запросы панели требуют `Idempotency-Key`: панель создаёт ключ на одно действие администратора и повторяет его при всех ретраях. Повтор с тем же ключом возвращает сохранённый ответ первого выполнения, и проверка `If-Match` к нему уже не применяется. Поэтому повтор успешной правки после обрыва связи не превращается в «Группу уже изменили». Тот же ключ с другим телом — 422 `IDEMPOTENCY_KEY_REUSED`. Ключи хранятся 24 часа.
- **Конкурентные правки.** `GET` возвращает `ETag` с версией. Правки заявок и назначений, снятие гида и передача партнёру требуют `If-Match`. Версия устарела — 412, нет заголовка или ключа — 428. Отмена заявки `If-Match` не требует: повторная отмена безопасна, а отменённую заявку изменить уже нельзя.
- **Ошибки** — RFC 9457 с полем `code`. У каждого кода есть действие для панели. Серверные ошибки и обрыв связи панель обрабатывает одинаково: повторяет с тем же ключом, после трёх неудач показывает «Не удалось сохранить, попробуйте ещё раз».
- **PATCH** — JSON Merge Patch (RFC 7396), `application/merge-patch+json`.
- **201** возвращает `Location`. Исключение — приглашение гида: его адрес и есть ссылка `t.me` в теле.
- **Вебхуки** отвечают сразу и обрабатываются асинхронно. Ответ 200 значит «сохранено», а не «обработано».
- **Телефоны** — E.164: `+79991112233`, `+375291234567`.

## Каталог ошибок

| code | HTTP | Когда | Что делает панель |
|---|---|---|---|
| VALIDATION_ERROR | 400 | Неверный формат поля или значения параметра | Подсвечивает поле из `errors` |
| UNAUTHORIZED | 401 | Сессия истекла | Просит войти и повторяет запрос с тем же ключом |
| NOT_FOUND | 404 | Нет такой заявки, группы, гида | Обновляет список |
| BOOKING_FROM_CRM | 409 | Заявку из amoCRM меняют в панели | Показывает ссылку на сделку в amoCRM; для отмены при недоступной amoCRM предлагает аварийную отмену |
| GUIDE_BUSY | 409 | У гида пересечение по времени с учётом буфера | Показывает пересечения из `overlaps` и список свободных гидов (`GET /v1/guides?freeForGroup=`) |
| GROUP_NOT_ASSIGNABLE | 409 | Группа отменена, передана партнёру или проведена | Обновляет карточку группы |
| GROUP_NOT_SEARCHING | 409 | Передать партнёру можно только группу в поиске | Обновляет карточку группы |
| DUTY_OVERLAP | 409 | В это время уже есть дежурный | Показывает текущее дежурство |
| VERSION_CONFLICT | 412 | Группу или заявку изменили после чтения | Перечитывает и показывает, что поменялось |
| START_IN_PAST | 422 | Время начала в прошлом | Подсвечивает время |
| ROUTE_NOT_FOUND | 422 | Маршрута нет в справочнике | Предлагает выбрать маршрут |
| GUIDE_NOT_ACTIVE | 422 | Гид не подтверждён или деактивирован | Предлагает другого гида |
| PARAMETER_READ_ONLY | 422 | P-01 или P-06 | Объясняет, что параметр меняется релизом |
| IDEMPOTENCY_KEY_REUSED | 422 | Ключ уже использован с другим телом | Дефект панели: в лог и мониторинг |
| PRECONDITION_REQUIRED | 428 | Нет `If-Match` или `Idempotency-Key` | Дефект панели: в лог и мониторинг |
