# Интеграции

Версия 0.3.

| Система | Направление | Протокол | Таймаут | Повторы | Дедупликация | Если система недоступна |
|---|---|---|---|---|---|---|
| [amoCRM, вебхуки](amocrm.md) | amoCRM → диспетчер | HTTP POST, form-urlencoded | отвечаем быстрее 2 с | amoCRM повторяет через 5 мин, 15 мин и 1 ч | сделка + действие + `last_modified` | Сверка раз в 15 мин по API (NFR-06) |
| [amoCRM, API v4](amocrm.md#api) | диспетчер → amoCRM | REST, OAuth 2.0 | 5 с | 3 повтора с паузой, при 429 — пауза | чтение | Событие остаётся необработанным и повторяется |
| [Telegram Bot API, обновления](telegram.md) | Telegram → диспетчер | вебхук с секретным заголовком | отвечаем сразу | Telegram повторяет недоставленное | `update_id` | Нажатия ждут у Telegram, пока диспетчер не ответит |
| [Telegram Bot API, сообщения](telegram.md#методы) | диспетчер → Telegram | HTTPS | 10 с | по `retry_after` при 429, с паузой при 5xx | `dedup_key` уведомления | Сообщения ждут в очереди |

Общие правила:
- Входящие вызовы сначала сохраняются, потом обрабатываются: ответ отправителю не зависит от времени обработки.
- Повторяются только таймауты, обрывы, 429 и 5xx. Ответы 4xx не повторяются, кроме 401 от amoCRM: после него токен обновляется и запрос повторяется один раз.
