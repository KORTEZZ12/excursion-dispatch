# Telegram Bot API

Интерфейс гида (D-02) и канал уведомлений администраторам. Telegram в России работает через VPN с задержками, поэтому механика назначения не зависит от того, чьё уведомление пришло раньше (D-11).

## Методы

| Метод | Зачем | Важное |
|---|---|---|
| `setWebhook` с `secret_token` | Получать обновления | Telegram присылает секрет в заголовке `X-Telegram-Bot-Api-Secret-Token`, без него запрос отклоняется (NFR-09) |
| `sendMessage` с `inline_keyboard` | Предложения, сводки, запросы подтверждения | Сообщение до 4096 символов. Для сообщений без срочности — `disable_notification`, без звука |
| `editMessageText`, `editMessageReplyMarkup` | Обновить предложение: «Группу получил другой гид», «Группа отменена» | Кнопки старого предложения убираются |
| `answerCallbackQuery` | Ответ на каждое нажатие кнопки | Без ответа у гида крутится индикатор загрузки |
| Deep link `t.me/<бот>?start=<токен>` | Подключение гида по приглашению (BR-28) | В токене до 64 символов A–Z, a–z, 0–9, `_` и `-` |

Данные кнопки (`callback_data`) — не больше 64 байт: `resp:<groupId>`, `skip:<groupId>`, `conf:<groupId>`. UUID с префиксом укладывается в лимит.

## Ограничения и ошибки

| Ситуация | Что делаем |
|---|---|
| Лимиты Bot API: в один чат — не чаще раза в секунду, всего — около 30 сообщений в секунду | Очередь отправки с ограничением скорости. При 30 гидах и 12 заявках в день лимит не мешает, но рассылка сводок идёт через ту же очередь |
| 429 Too Many Requests с `retry_after` | Ждём указанное время и повторяем |
| 403 «bot was blocked by the user» | Не повторяем. Отмечаем `bot_blocked_at`, гид исключается из предложений, по его группам эскалация (BR-31) |
| 400 «message is not modified» | Игнорируем: сообщение уже в нужном виде, повторное редактирование безопасно |
| Ответ на старое нажатие не принимается | Игнорируем, гид видит актуальное состояние в сообщении |
| Таймаут, 5xx | Повтор с паузой и случайным разбросом |
| Одно обновление пришло дважды | Обрабатываем по `update_id` один раз |
