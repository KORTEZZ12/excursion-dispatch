# Как устроена работа над проектом

Проект учебный, команда — симуляция. Я системный аналитик, остальные роли выполняют ИИ-агенты. Так я прохожу полный цикл аналитики — от исследования до приёмки MVP — с ревью на каждом шаге.

| Роль | Кто | Что делает |
|---|---|---|
| Системный аналитик | я | Доменные правила из опыта гида, интервью, решения, ревью черновиков, приёмка |
| Аналитик-помощник | ИИ (Claude) | Черновики артефактов по моим вводным |
| Заказчик | ИИ-агент с персоной владельца экскурсионной службы | Приоритеты, изменения по ходу проекта |
| Ревьюер требований | ИИ, скиллы `/sar` и `/sar-crosscheck` в отдельном чате | Независимое ревью требований и контрактов |
| Архитектор | ИИ-агент | Ревью решений и НФТ |
| Разработчик | ИИ-агент (Claude Code) | MVP по утверждённой спецификации, вопросы аналитику в issues |
| QA | ИИ-агент | Тест-кейсы по критериям приёмки |

Решения принимаю я. Черновик становится частью проекта после моего ревью, правки видны в истории PR.

## Итерации

| № | Что | Статус |
|---|---|---|
| 1 | AS-IS по опыту, гипотезы, гайд интервью, TO-BE и бэклог | готово |
| 2 | Интервью, требования, системный дизайн: модель данных, OpenAPI, интеграции, sequence, состояния, ADR | готово, ждёт независимого ревью |
| 3 | MVP, тест-кейсы, приёмка | — |
| 4 | Независимое ревью, изменение от заказчика, ретро | — |

## Цикл одной истории

1. Заказчик приносит запрос — заводится issue.
2. Встреча с заказчиком, протокол, история с критериями приёмки.
3. Спецификация в отдельной ветке и PR.
4. Ревью: `/sar`, архитектор, `/sar-crosscheck`. Замечания — комментариями в PR, ответы и правки там же.
5. Merge, карточка переходит в Ready for Dev, разработчик собирает. Если в спецификации дыра, он не додумывает, а заводит issue «Вопрос аналитику».
6. QA проверяет, я принимаю по критериям и размечаю дефекты: ошибка кода или ошибка требований.
7. В конце итерации — демо заказчику и ретро.

## Доска

GitHub Projects, колонки: Backlog → Analysis → Review → Ready for Dev → In Dev → Testing → Done. Шаблоны задач лежат в `.github/ISSUE_TEMPLATE`, в `main` изменения попадают только через PR.
