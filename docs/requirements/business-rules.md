# Бизнес-правила

Версия 0.3. Источник «исследование» — [итоги исследования](../research/findings.md).

У каждого правила указан источник:
- **практика** — так служба работает сейчас, по моему опыту гида;
- **решение** — правило нового процесса из [журнала решений](../decisions/decision-log.md);
- **исследование** — подтверждено или найдено на интервью;
- **допущение** — типовой вариант, не проверялся.

Числа вынесены в [параметры](#параметры): служба меняет их без доработки системы.

## Группы и данные заявки

| ID | Правило | Источник |
|---|---|---|
| BR-01 | Группа — от 1 до 15 участников с одним гидом (P-01) | практика |
| BR-02 | Заявка на N участников делится на ⌈N / 15⌉ групп. Участники распределяются поровну: размеры групп отличаются не больше чем на одного человека. Пример: 40 → 14, 13, 13 | решение D-05 |
| BR-03 | Группы одной заявки начинаются в одно время и идут по одному маршруту | допущение |
| BR-04 | Данные заявки (клиент, дата и время, маршрут, число участников, способ оплаты) ведутся в CRM. Диспетчер ведёт группы, назначения, уведомления и эскалации. Для заявки из CRM панель показывает её данные только для чтения, изменения вносятся в CRM | решение D-04 |

## Поиск и назначение гида

| ID | Правило | Источник |
|---|---|---|
| BR-05 | Предложение получают все активные гиды без назначенной группы, которая пересекается с этой по времени с учётом буфера P-02, и без отметки «не работаю» на эту дату (BR-10) | решение D-03 |
| BR-06 | Гиды откликаются кнопкой «Хочу взять» в течение окна P-21 (10 мин), для группы, до которой меньше 4 ч, — в течение P-22 (2 мин). Когда окно закрывается, группа достаётся откликнувшемуся гиду с наименьшим числом групп на неделе этой группы (пн–вс по Москве), при равенстве — случайно. Если за окно никто не откликнулся, группу получает первый, кто нажмёт после. Нажатие принимается только от активного гида, которому это предложение отправлено. У остальных предложение меняется на «Группу получил другой гид» | решение D-11 |
| BR-07 | Пересечение по времени проверяется и при нажатии, и при выборе гида по окну: за это время гид мог получить другую группу. Кандидат с пересечением пропускается, группа достаётся следующему | решение |
| BR-08 | Если гид не назначен, дежурный администратор получает эскалацию «Гид не найден». Срок зависит от того, сколько осталось до начала в момент создания группы:<br>• больше P-04 (24 ч) — через P-03 (3 ч) после создания или за P-04 до начала, что наступит раньше;<br>• от 1 до 24 ч — через P-05 (30 мин) после создания;<br>• меньше 1 ч — сразу после окна откликов.<br>Сроки P-03 и P-05 считаются вне тихих часов (BR-14). После эскалации предложения остаются активными: группу может взять гид в боте или назначить администратор | решение |
| BR-09 | Администратор может назначить любого активного гида вручную. Если у гида пересечение по времени, панель предупреждает, назначение возможно только после явного подтверждения. Администратор может снять гида с группы: группа возвращается в поиск, гид получает уведомление | решение |
| BR-10 | Гид может отметить даты, когда не работает. В эти даты предложения ему не приходят | решение |

## Напоминания гиду

| BR-12 | Если группу назначили после отправки сводки, гид получает сообщение сразу при назначении | решение |
| BR-13 | За P-07 (2 ч) до начала гид получает запрос с кнопками «Подтвердить выход» и «Попросить замену». Если ответа нет к P-08 (1 ч до начала), создаётся эскалация «Нет подтверждения». Если группу назначили позже чем за P-07 до начала, запрос приходит сразу. Для групп, которые начинаются раньше 09:00, запрос приходит вместе со сводкой накануне | решение |
| BR-14 | В тихие часы P-09 (22:00–07:00) плановые сообщения не отправляются и переносятся на 07:00. Без переноса отправляются сообщения о группах, которые начинаются в ближайшие 12 ч: предложения, отмены, изменения, эскалации | решение |

## Клиент

| ID | Правило | Источник |
|---|---|---|
| BR-15 | Отписка одна на заявку, даже если групп несколько. Содержание: дата, время и место сбора со ссылкой на точку на карте и фото места, маршрут, способ оплаты, имя и телефон каждого гида, правило отмены. Канал — мессенджер, который клиент назвал при записи: Telegram, MAX или WhatsApp. Накануне в P-10 (12:00) система готовит текст и ссылку на чат с клиентом, администратор отправляет со служебного аккаунта и отмечает отправку. Если у какой-то группы ещё нет гида, подготовка ждёт назначения, но не дольше P-11. Если заявка создана позже P-10, отписка готовится сразу после назначения гидов | практика + решение D-07 + исследование (карта и фото) |
| BR-16 | Если к P-11 (18:00 накануне) отписка не отмечена отправленной, сообщение получают все администраторы. Если выбранный мессенджер не работает, администратор отправляет в другой или звонит и отмечает фактический канал | решение |
| BR-17 | Клиент получает телефон гида, чтобы уточнять детали напрямую. Гид даёт согласие на передачу номера клиентам при подключении к боту (BR-28) | практика + решение D-08 |
| BR-34 | Если после отправки отписки у группы сменился гид, дежурный получает задачу сообщить клиенту имя и телефон нового гида. Система готовит текст так же, как для отписки | решение |

## Изменения и отмены

| ID | Правило | Источник |
|---|---|---|
| BR-18 | Отмена клиентом. Не позднее чем за P-12 (24 ч) до начала — без последствий, заранее переведённые деньги возвращаются полностью. Позже — заранее переведённые деньги не возвращаются, администратор может предложить перенос. Обычно клиенты платят на месте, поэтому денежная часть касается только заранее сделанных переводов | допущение |
| BR-19 | Отмена службой (погода, болезнь гида и т. п.): клиенту предлагают перенос или полный возврат. При болезни гида сначала ищут замену, отменяют, только если её нет | допущение |
| BR-20 | При отмене заявки отменяются все её группы. Назначенные гиды получают уведомление (с учётом BR-14), предложения отзываются, запланированные напоминания и отписка отменяются | решение |
| BR-21 | При изменении даты или времени назначения сохраняются, гид получает запрос «Подтвердить новое время». Группа возвращается в поиск, если гид не подтвердил за P-13 (2 ч, считаются вне тихих часов) или новое время пересекается с другой его группой. Гид получает уведомление о снятии | решение |
| BR-22 | При изменении числа участников:<br>• число групп не меняется — участники перераспределяются по BR-02, гиды получают новое число;<br>• групп стало больше — новая группа уходит в поиск;<br>• групп стало меньше — сначала снимаются группы без гида, затем группа, гид которой назначен последним; этот гид получает уведомление | решение |
| BR-23 | Отказ гида от назначенной группы. Больше чем за P-14 (24 ч) до начала — сам, в боте: группа возвращается в поиск, администратор получает информационное уведомление. Позже — кнопка «Попросить замену» создаёт эскалацию, гид остаётся назначенным, пока администратор не найдёт замену или не снимет его | решение D-10 |
| BR-24 | Опоздавших ждут P-15 (15 мин) и звонят им. При сильном опоздании гид сокращает маршрут. Если клиенты так и не пришли, гид отмечает «Клиенты не пришли», группа переходит в статус «Не состоялась», администратор получает уведомление | практика |

## Эскалации

|---|---|---|
