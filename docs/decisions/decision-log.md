# Журнал решений

Продуктовые решения. Статусы: **предложено** — ждёт подтверждения, **принято**, **отклонено**. Все решения итерации 1 подтверждены, D-07 и D-08 изменены по практике службы. После исследования D-03 заменено решением D-11. D-12–D-16 предложены по [ревью итерации 2](../reviews/2026-10-27-iteration-2/README.md) и приняты владельцем службы 28 октября 2026. D-17 — по опросу гидов, D-18 — по совету юриста, оба ждут подтверждения владельца. Архитектурные решения — в папке [`adr`](adr).

| D-01 | Основной пользователь MVP — гид, второй — администратор. Клиент только получает уведомления | Все боли из AS-IS лежат на стыке «администратор → гид» | MVP для клиента с онлайн-записью | Г3 | принято |
| D-02 | Интерфейс гида — Telegram-бот | Гиды уже каждый день в Telegram, ничего не нужно устанавливать | Мобильное приложение; веб-кабинет | Г5 | принято |
| D-03 | Назначение по правилу «кто первым взял», как сейчас в чате, но с проверкой пересечений и атомарным закреплением | Привычная механика, минимум изменений для гидов | Адресное предложение по очереди (US-23) | Г8 | заменено D-11: Г8 опровергнута |

Если за окно никто не откликнулся, группу получает первый, кто нажмёт | Скорость доставки уведомлений через Telegram и VPN у гидов разная, гонка нечестная и проигрывают те, кто ведёт экскурсию (П6, Г8) | «Кто первым нажал» (D-03); адресная очередь с таймаутом на ответ | Г8, Г11 | принято; для срочных групп гонка частично остаётся — принятый компромисс, разбор и уточнения v0.4 — [ADR-002](adr/ADR-002-response-window.md) |
