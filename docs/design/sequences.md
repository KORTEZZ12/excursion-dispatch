# Sequence-диаграммы

Версия 0.4. Вызовы и коды совпадают с [OpenAPI](../api/openapi.yaml), интеграции — с [amoCRM](../integrations/amocrm.md) и [Telegram](../integrations/telegram.md), гарантии — с [моделью данных](data-model.md). На диаграммах — операции и бизнес-результаты, а не функции и ограничения базы: если выбор гида переедет из базы в код, диаграммы останутся правдой.

| Диаграмма | Что разбирает |
|---|---|
| [SD-1. Заявка из amoCRM](#sd-1-заявка-из-amocrm) | Вебхук как сигнал, дубли, устаревшие события, правки в одну секунду |
| [SD-2. Окно откликов и честный выбор](#sd-2-окно-откликов-и-честный-выбор) | D-11, пересечения, ручное назначение во время окна |
| [SD-3. Сводка и подтверждение выхода](#sd-3-сводка-и-подтверждение-выхода) | US-08, US-09, эскалация «Нет подтверждения» |
| [SD-4. Отписка клиенту](#sd-4-отписка-клиенту) | US-10, крайний срок, смена гида до и после отписки |
| [SD-5. Сбои Telegram](#sd-5-сбои-telegram) | 429, 5xx, 403, срок годности, повтор обновления |
| [SD-6. Поздний отказ и замена](#sd-6-поздний-отказ-и-замена) | US-14, «Попросить замену» в любой момент, новое назначение |

## SD-1. Заявка из amoCRM

amoCRM ждёт ответ не дольше 2 секунд, поэтому вебхук только сохраняется. Данные сделки берутся из API: вебхук — сигнал, а не источник правды ([ADR-001](../decisions/adr/ADR-001-webhook-as-signal.md)).

```mermaid
sequenceDiagram
  autonumber
  participant CRM as amoCRM
  participant D as Диспетчер
  participant W as Обработчик событий
  CRM->>D: POST /integrations/amocrm/webhook/{secret}, leads[update][0][id]
  D->>D: сохранить событие, повтор того же события не сохраняется второй раз
  D-->>CRM: 200 быстрее 2 с
  W->>D: взять следующее событие сделки, когда предыдущее применено
  W->>CRM: GET /api/v4/leads/{id}?with=contacts
  CRM-->>W: сделка, updated_at, поля, контакт
  W->>D: применить состояние сделки
  alt сделка новая
    D-->>W: создана, группы 14, 13, 13, поиск гида запущен
  else updated_at новее или то же, но данные другие
    D-->>W: изменена, правила BR-21 и BR-22
  else то же время и те же данные
    D-->>W: без изменений
  else updated_at старее сохранённого
    D-->>W: устаревшее, событие только отмечается
  end
  Note over CRM,W: если вебхуки не приходят, раз в 15 мин сверка с момента последней успешной
```

## SD-2. Окно откликов и честный выбор

Скорость доставки уведомлений Telegram у гидов разная, поэтому порядок нажатий в окне не важен, а само окно отсчитывается от последнего отправленного предложения ([ADR-002](../decisions/adr/ADR-002-response-window.md)).

```mermaid
sequenceDiagram
  autonumber
  participant D as Диспетчер
  participant TG as Telegram
  participant A as Гид А
  participant B as Гид Б
  D->>TG: предложения свободным гидам, раунд 1
  TG->>B: предложение, доставлено через 2 с
  TG->>A: предложение, доставлено через 15 с
  D->>D: последнее предложение отправлено в 11:00, окно до 11:10
  B->>TG: «Хочу взять»
  TG->>D: нажатие Б, раунд 1
  D->>TG: «Вы в числе кандидатов, решение в 11:10»
  A->>TG: «Хочу взять»
  TG->>D: нажатие А, раунд 1
  D->>TG: «Вы в числе кандидатов, решение в 11:10»
  Note over D: 11:10, окно закрылось
  D->>D: выбрать среди кандидатов того, у кого меньше групп на неделе: у А 3, у Б 5
  alt у А нет пересечения по времени
    D->>D: назначен А
  else у А за это время появилась группа в то же время
    D->>D: А пропущен, назначен Б
  end
  D->>TG: назначенному — «Группа ваша»
  D->>TG: остальным — «Группу получил другой гид»
  Note over D,B: если администратор назначил гида до 11:10, выбор не выполняется
```

## SD-3. Сводка и подтверждение выхода

Подтверждение — одно на день гида, перед первой группой (BR-13, D-15).

```mermaid
sequenceDiagram
  autonumber
  participant P as Планировщик
  participant D as Диспетчер
  participant TG as Telegram
  participant G as Гид
  participant ADM as Дежурный
  P->>D: 19:00, собрать группы на завтра по гидам
  D->>D: поставить сводку гиду на дату, повтор не создаст вторую
  D->>TG: сводка на завтра
  TG->>G: ваши группы на завтра: 10:00 и 12:00
  P->>D: 08:00, за 2 ч до первой группы дня
  D->>TG: «Подтвердить выход» и «Попросить замену»
  alt гид подтвердил
    G->>TG: «Подтвердить выход»
    TG->>D: нажатие по назначению
    D->>D: обе группы дня — «Гид подтвердил», по группе в 12:00 запроса не будет
  else нет ответа к 09:00
    D->>D: эскалация «Нет подтверждения»
    D->>TG: сообщение дежурному с кнопкой «Взять в работу»
    TG->>ADM: эскалация
    Note over D,ADM: 15 минут без реакции — эскалацию получают все администраторы
    G->>TG: «Подтвердить выход» в 09:10
    D->>D: подтверждено, эскалация закрыта сама
  end
```

## SD-4. Отписка клиенту

Текст отписки собирается при каждом открытии задачи, а фиксируется в момент «Отправлено» (BR-15, BR-16).

```mermaid
sequenceDiagram
  autonumber
  participant P as Планировщик
  participant D as Диспетчер
  participant ADM as Администратор
  participant C as Клиент
  P->>D: 12:00 накануне, все гиды заявки назначены?
  alt все назначены
    D->>D: задача «Отправить отписку», срок 18:00
  else кого-то нет
    D->>D: ждать назначения, но не позже 18:00
  end
  ADM->>D: GET /v1/notices
  D-->>ADM: текст с актуальными гидами, картой и фото, ссылка на чат
  ADM->>C: текст в Telegram по ссылке на чат
  ADM->>D: POST /v1/notices/{id}/sent, канал TELEGRAM, отправленный текст
  D-->>ADM: 200, задача закрыта
  Note over P,ADM: к 18:00 не отмечено — эскалация «Отписка не отправлена к сроку» всем администраторам
  Note over D,C: гид сменился после отправки — задача «Сообщить клиенту о новом гиде»
```

## SD-5. Сбои Telegram

```mermaid
sequenceDiagram
  autonumber
  participant Q as Очередь отправки
  participant TG as Telegram
  participant D as Диспетчер
  participant ADM as Администраторы
  Q->>TG: sendMessage
  TG-->>Q: 429, retry_after 7
  Q->>Q: пауза 7 с
  Q->>TG: sendMessage, повтор
  TG-->>Q: 200, message_id
  Q->>TG: sendMessage гиду В
  TG-->>Q: 403, bot was blocked by the user
  Q->>D: гид заблокировал бота
  D->>D: гид исключён из предложений, эскалация «Гид заблокировал бота» по его группам
  Q->>TG: предложение гиду Г
  TG-->>Q: 502, 502, 502
  Q->>Q: окно уже закрылось — срок годности истёк, не отправляем
  Note over Q,ADM: Telegram не отвечает дольше 5 минут — тревога администраторам по резервному каналу
  TG->>D: обновление update_id 734119021
  TG->>D: то же обновление повторно
  D->>D: update_id уже обработан, второй раз не применяется
```

## SD-6. Поздний отказ и замена

«Попросить замену» работает всё время назначения, а не только в ответ на запрос подтверждения (BR-23).

```mermaid
sequenceDiagram
  autonumber
  participant G as Гид А
  participant TG as Telegram
  participant D as Диспетчер
  participant ADM as Дежурный
  participant G2 as Гид Б
  G->>TG: «Попросить замену» в карточке группы, за 20 ч до начала
  TG->>D: нажатие по назначению А
  D->>D: эскалация «Гид просит замену» по назначению А, гид А остаётся назначенным
  D->>TG: эскалация дежурному
  TG->>ADM: эскалация
  ADM->>D: PUT /v1/groups/{id}/assignment, гид Б
  D->>D: новое назначение Б, подтверждение А к нему не переходит
  D->>TG: гиду А — «Вы больше не ведёте группу», гиду Б — «Группа ваша»
  D->>D: эскалация закрыта: причина устранена
  Note over D,G2: подтверждать выход будет Б, эскалации по нему создаются заново
```
